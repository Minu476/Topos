# Plan: Use Topos as a backend for NexusVerifier's proof-search backward chainer

## Goal

Use Topos for real in a second (non-RLB) domain — NexusVerifier's AND-OR proof-search backward chainer — to (a) confirm the kernel serves a domain it wasn't designed around, purely via public API, and (b) surface real issues in Topos that only show up under genuine use. This is the "faithful port" scope: a real integration with bounded risk, explicitly *not* a rewrite of NexusVerifier's search logic.

## Scope decisions (defaults — override if any is wrong)

1. **Faithful port, not n-ary chainer rewrite.** Topos stores the tactic graph natively as n-ary (one Edge-vertex per tactic-application, N subgoal members), but at the boundary we still project to V2's `HyperEdge` (1 Anchor + N Conditions + 1 Target) so `NexusBackwardChainer` runs effectively unmodified. This tests "Topos as a clean storage backend" without rewriting search logic. *Deferred, its own decision later:* a chainer that consumes Topos's native n-ary shape directly — that's where Topos's structural advantage would actually show, but it's a bigger change to what NexusVerifier *is*.

2. **New parallel project, not edits to `RlbExperiment`.** Per the future-work doc's discipline (RLB pinned, baseline preserved), the Topos work lives in a new `NexusAgent.ToposExperiment` project alongside `RlbExperiment`. The ~6 concrete-type couplings (`InMemoryGraphMemory` → `IGraphMemory`) are applied to *copies* of the shared files in the new project, not to the frozen baseline. RlbExperiment stays as the V2 reference for parity comparison.

3. **Branch off `master`, not off `rlb-v2-experiment`.** The experiment branch is paused/close-out; clean Topos work shouldn't inherit its state.

4. **Synthetic fixture (default) + shared Neo4j (opt-in).** Unit tests always run against a synthetic `AppliesEdge` fixture with *real junctions* (the structural property FC100 lacked — sidesteps the prior NO-GO's data problem for a structural test). An opt-in parity test loads the real `nexusdb` graph and compares to V2, skipping gracefully if the shared Neo4j Desktop instance is unreachable (the GDS-oracle pattern Topos already uses).

## What gets built

### In NexusVerifier (new branch off `master`)

**New project `NexusAgent/NexusAgent.ToposExperiment/`** (.NET 10, `Exe`), referencing `NexusAgent.Core` and Topos via `ProjectReference` (Topos at `/Users/nassertowfigh/Projects/Topos/src/Topos.Hypergraph`). Files:

- **`Memory/ToposGraphMemory.cs`** — implements `IGraphMemory` (from `RichLearning.V2.Abstractions`). Exercises only the surface the chainer actually calls: `SupportsHyperedges => true`, `GetHyperedgesByMemberAsync`, `UpsertHyperedgeAsync`, `UpsertLandmarkAsync` (no-op — Topos has its own member index), `InitialiseSchemaAsync` (no-op, like `InMemoryGraphMemory`), `DisposeAsync`. All other interface methods fall through to the interface's default `NotSupportedException` implementations. **Critical contract:** caches and returns *reference-stable* `HyperEdge` objects by `StateKey` — the same id queried twice yields the same instance — so `CreditAssignment`'s `ReinforceTheta` writes are visible to subsequent reads and the L9 eval-freeze assert holds. Backed by a `HypergraphKernel` for genuine n-ary storage.

- **`Ingest/ToposAppliesAdapter.cs`** — mirrors `AppliesHyperedgeAdapter`. Consumes `IReadOnlyList<AppliesEdge>` (same record, reused verbatim — no data-format change). Native n-ary storage in Topos: one `CreateVertex(VertexRoles.Edge)` per `(GoalBeforeHash, TacticId)` group; one member vertex per distinct goal hash (deduped across the whole graph via a `Dictionary<string, Handle>`); `AddIncidence(edge, member, role, ordinal)` with adapter-owned role bytes (`const byte BeforeRole = 0, AfterRole = 1`). Then projects each Topos edge-vertex to a V2 `HyperEdge` (Anchor = before-goal, Conditions = after-subgoals, Target = before-goal to satisfy V2 cardinality — the same "L12 uniform mapping" the existing adapter uses, since the chainer consumes V2 shape) and caches it for reference-stable return. Properties (`TransitionCount`, `SuccessRate`, `Confidence`) attach to the edge-vertex (the `ChatMemory.RecordRecallFeedback` pattern), since Topos's per-incidence property mechanism wasn't actually built (see issues log).

- **Shared files, copied + loosened** — `Search/NexusBackwardChainer.cs`, `Training/TrainingLoop.cs`, `Training/CreditAssignment.cs`, `Eval/EvalHarness.cs`, `Sanity/SanityTripwire.cs`, `Search/SearchArm.cs`, `Search/ProofSearchResult.cs`, `Telemetry/EpisodeTelemetry.cs`, `Models/AppliesEdge.cs`, `Models/GoalEntry.cs`, `Ingest/RlbGraphLoader.cs` (renamed conceptually but kept as-is — it's just a Neo4j reader). The *only* edits to these copies: `InMemoryGraphMemory` → `IGraphMemory` in field/param/return declarations (~6 sites). Search logic, credit-assignment math, eval freeze — untouched.

- **`Program.cs`** — same CLI shape as the V2 experiment (`--seed`, `--fuel`, `--episodes`, `--run-training`, `--run-eval`), plus a `--backend topos|v2` flag so the same harness can run against either backend for side-by-side comparison. Defaults to `topos`.

- **`Fixtures/SyntheticAppliesGraph.cs`** + **`Fixtures/SyntheticAppliesGraphTests.cs`** — a factory producing `AppliesEdge` records with deliberately-real junctions: 2-3 tactics reaching the same intermediate goal (branching factor > 1, which FC100 lacked), a shared subgoal across two theorem-proofs (a real junction), and a few multi-subgoal tactic applications (genuine n-ary). Hand-computed expected AND-OR search results asserted against.

- **`Parity/Neo4jParityTests.cs`** — opt-in, `[Fact]` with early `return` if `Neo4jTestConfig`-style probe can't reach the shared Desktop instance. Loads `nexusdb` via `RlbGraphLoader`, builds a `ToposGraphMemory`, runs the chainer, asserts solve rate / mean steps match a recorded V2 baseline (CSV checked in from a prior V2 run, or live both-backends comparison).

- **`docs/TOPOS_INTEGRATION_REPORT.md`** — what was built, parity results, and the issues log (below).

## Tests / parity strategy

1. **Synthetic unit tests (always run):** `SyntheticAppliesGraphTests` loads the fixture into `ToposGraphMemory`, runs the chainer, asserts results match hand-computed AND-OR over the same graph. Covers: leaf closure, AND-branch over multiple subgoals, OR-branch across competing tactics, cycle guard, fuel exhaustion. This is the primary correctness gate and has zero external dependencies.

2. **Reference-stability test:** asserts that `GetHyperedgesByMemberAsync` returns the same `HyperEdge` instance across calls (reference equality), and that mutating one via `ReinforceTheta` is visible through a subsequent read — the contract `Program.BuildHyperedgeIndexAsync` + `CreditAssignment` rely on.

3. **L9 eval-freeze canary:** runs the eval harness (read-only) and confirms the bit-identical-theta assertion holds against the Topos backend. This is the canary for the reference-stability contract being violated.

4. **Neo4j parity (opt-in):** if the shared Desktop instance is up and `nexusdb` loaded, runs the chainer over the real 267k-node graph in both backends and compares solve rates / mean steps / theta-update counts. The prior experiment's own parity standard (the credit-loop bit-identical test) is the bar.

5. **Build + existing tests still green:** `dotnet build NexusAgent.sln` clean; the 96 existing `NexusAgent.Tests` unaffected (new project is additive).

## Issues the integration is explicitly designed to surface (fed back to Topos M8)

These are the real epistemic payload, not just engineering:

1. **Cell-level (per-Incidence) properties are documented but not built.** `Incidence.cs:12-17` promises per-(source,member,ordinal) property addressing "lands with M2's reification work"; M2 shipped nested reification only. The adapter works around it by attaching stats to the edge-vertex, losing per-subgoal granularity. This is a real doc-vs-code divergence.
2. **Reference-stability contract is undocumented and load-bearing.** The chainer+credit-assignment path requires backends to return the same `HyperEdge` instance per id (no defensive copy on read). `InMemoryGraphMemory` honors this for hyperedges but clones landmarks/transitions — inconsistent, and nothing in the interface warns an implementer. A Topos (or any) backend that materialized fresh POCOs would silently break credit assignment.
3. **Role-typing is a free `byte`.** Workable (`ChatMemory` does it), but the absence of any role registry / typed-enum convention means every consumer reinvents the mapping with no compile-time help. Worth a layer-1 convention note.
4. **`IHypergraphQuery.HasCycle` is misleading on n-ary graphs** (returns true for nearly any 3+-member hyperedge). The doc already flags this, but a backward-chaining consumer reaching for cycle detection would get burned.
5. **No role-aware traversal at the kernel layer.** A proof-search consumer must hand-roll role-filtered walks over `GetHyperedgeVertices` + `Incidence.Role` (the `ChatMemory.EntitiesMentionedIn` pattern). Acceptable by design ("the kernel does not judge"), but worth confirming the layer-1 API story for directed/role-gated search is on the M8 list.

## Honest caveats

- **This scope does NOT exercise Topos's n-ary advantage at the chainer level.** The boundary projection re-imposes V2's Anchor/Target shape. The genuine structural win (one tactic-edge → N subgoals with no contortion) only shows in the *deferred* n-ary chainer rewrite. This milestone proves "Topos is a clean, correct storage backend for a second domain" — not "Topos makes the search better." That's the trade for bounded risk.
- **The Neo4j parity run depends on the shared Desktop instance.** If `nexusdb` isn't loaded or the instance is down, parity is skipped and only the synthetic result stands. The synthetic fixture is designed so the structural test is meaningful on its own.
- **Topos's cell-property gap is worked around, not fixed.** Per-subgoal success rates aren't natural in Topos today; the integration records per-tactic-edge rates instead. This is a *finding* for M8, not a blocker for this milestone — but it means the parity comparison is slightly apples-to-oranges on the granularity of learning signal, even if aggregate solve rates match.
- **~6 mechanical edits to copied NexusVerifier files** (the `InMemoryGraphMemory` → `IGraphMemory` loosening). The original `RlbExperiment` source is untouched.

## Exit criteria (what "done" looks like)

1. `NexusAgent.ToposExperiment` builds clean; synthetic unit tests pass; reference-stability + L9-freeze canaries pass.
2. Chainer runs against `ToposGraphMemory` over the synthetic fixture and produces correct AND-OR search results (hand-computed parity).
3. (If shared Neo4j available) Topos-backed run over `nexusdb` matches V2-backed run on solve rates / mean steps, within the experiment's own parity tolerance.
4. Existing 96 `NexusAgent.Tests` still pass; `RlbExperiment` project untouched.
5. `docs/TOPOS_INTEGRATION_REPORT.md` written with parity results and the issues log above, suitable for feeding into Topos's M8 API-stability review.

## Explicitly out of scope

- N-ary chainer rewrite (the option-2 scope — separate decision after this lands).
- The §4 pre-flight / Mathlib-scale re-ingest / Phase B learning experiment (P-B2.2). This milestone makes no learning-result claim; the §4 gate doesn't apply because we're not claiming V2 *works*, just that Topos can be the backend.
- Any change to Topos source. Issues go to the log, not the codebase, in this milestone.
