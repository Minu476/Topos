## What this is

A full **user-facing documentation set** for Topos — the first one in the repo. Today the `docs/` tree has only research/spec/process artifacts (adjudication-grade, written to settle design questions), and `README.md` is a status doc. There is *nothing* that teaches someone what a `Handle` is or how to write their first hyperedge. The excellent in-code XML doc comments only surface if you read `.cs` files directly. This closes that gap.

Five Markdown pieces, all matching the existing findings-doc house style (`ROLE_CONVENTIONS.md`/`GDS_ALGORITHM_TIERS.md`): dated headers, direct opinionated prose, inline `[verified:src=path]` tags on every non-trivial claim, cross-references to spec §/`docs/` rather than re-explaining settled material.

**Lane (per `docs/GLM_DOCUMENTATION_GUIDELINES.md`):** Markdown in `docs/` + `README.md` only. No `src/`/`.cs` edits, no `.csproj`/site tooling (the docs-*site* with DocFX is the separately-deferred M8 item, gated on go-public — out of scope here). Every claim tagged `[verified:...]`. Record, never announce, milestone status.

### 2. `docs/CONCEPTS.md` — the mental model (the centerpiece)
- The one doc a new user reads to *understand* Topos. Cross-references spec §3/§4 for depth instead of duplicating.
- Sections: **The four primitives** (`Handle`, `Vertex`, `Incidence`, `PropertyKey<T>`) — one paragraph each on *why* the shape is what it is, with the actual signatures from source; **The two invariants** (dormant-never-GC'd; roles-and-status-are-independent) stated as operational rules; **Roles vs. VertexRoles** — the single most confusing fork, called out explicitly (kernel `VertexRoles` bitmask vs. layer-1 `Incidence.Role` byte, "the kernel records, it does not judge"); **The layer architecture** — 3-layer substrate, why role-awareness lives in `Topos.Hypergraph.Knowledge` not the kernel; **Hyperedges as reified vertices** — the `VertexRoles.Edge` pattern that makes n-ary first-class; **What Topos is not** (not an extraction pipeline, not a server, not a reasoning engine — lifted from spec §2.2).
- `[verified:src=...]` tags point at `Handle.cs`, `Vertex.cs`, `Incidence.cs`, `PropertyKey.cs`, `IHypergraphQuery.cs`.

### 3. `docs/GETTING_STARTED.md` — runnable walkthrough
- A linear, copy-pasteable narrative from "create a kernel" to "run a directed traversal," adapted (and *stripped of its M5-falsifiability framing*) from the real code in `samples/Topos.Samples.ChatMemory/`.
- Flow: construct `HypergraphKernel` → resolve `PropertyKey<T>`s → create vertices → build an n-ary hyperedge via `CreateVertex(VertexRoles.Edge)` + `AddIncidence` → query it with `GetVertexHyperedges`/`RoleFilteredMembers` → run a kernel algorithm (`IsReachable`/`GetShortestPath`) → save/reload with `HypergraphSnapshot`.
- Uses the **byte-backed-enum role pattern from `docs/ROLE_CONVENTIONS.md`** (not the sample's pre-convention `const byte` fields) to stay consistent with the locked M8/M9 convention.
- Shows building against the source via `ProjectReference` (verified — no NuGet exists); notes `dotnet build Topos.sln` / `dotnet test Topos.sln` as the build/test commands.

### 4. `docs/API_REFERENCE.md` — hand-written prose catalog
- One section per public type, grouped by layer/package: **kernel** (`HypergraphKernel`, `IHypergraphQuery`, `Handle`, `Vertex`, `Incidence`, `PropertyKey<T>`/`PropertyRegistry`, `HandleAllocator`, `VertexRoles`, `VertexStatus`) → **reification/semantics** (`AssertionMode`, `Provenance`) → **views** (`HypergraphViews`, `FilteredView`, `UnionView`) → **embeddings/learnable** (`VectorIndex`, `LearnableEdge`, `EdgeStatistics`) → **analytics** (`SWalk`, `LabelPropagation`, `TriangleCount`, `Modularity`) → **persistence** (`HypergraphSnapshot`, `IPersistedPropertyColumn`, `PersistedProperty`, `LruCache<,>`) → **knowledge (M9)** (`DirectedTraversal`, `RoleExtensions`).
- Each type: one-sentence purpose, the load-bearing public members with signatures, when-to-use / when-not, and a `src/...cs` cross-ref. **Internal types explicitly listed as "not public API"** (`SparseSet<T>`, `PropertyPool<T>`, `IncidenceIndex`, `BipartiteAdjacency`, generic `PersistedPropertyColumn<T>`) with the one-line "why it's internal" and the `InternalsVisibleTo` note — so a reader doesn't go hunting for them.
- Calls out the non-obvious operational facts surfaced during exploration: no dedicated reification method (it's a usage pattern); `AssertionMode`/`Provenance` are `PropertyKey<T>` values, not reserved fields; `RestoreVertex` is the only sanctioned Invariant-1 bypass; the M5/M6 "derived" types add no kernel storage.

### 5. `docs/USAGE_PATTERNS.md` — when-to-use guide
- The opinionated companion to the reference: how to model common agent-memory shapes in Topos.
- Patterns (each a worked mini-example, cross-ref to where it's used for real): **N-ary facts as one hyperedge** (ChatMemory's `RecordMention` — the thesis); **Reification: edges as vertices** (asserted/quoted/hypothesized mode, nested reification for structural provenance); **Typed properties + side index for per-cell data** (the M8-decided workaround since there's no `SetProperty(key, incidence, value)`); **Composable views** (subgraph/mask/union/intersect/diff, plus the monotonic-Handle version-diff trick); **Semantic recall** (`VectorIndex` over `PropertyKey<float[]>`); **Learnable edges** (`LearnableEdge`/`EdgeStatistics` reinforcement loop); **Persistence** (snapshot save/load with `PersistedProperty` columns); **Directed traversal** (M9's `DirectedBfs`/`RoleFilteredMembers` with byte-backed-enum roles).
